# Coolify Deployment

This app is deployed as one Docker Compose application:

- `db`: PostgreSQL 18, matching the Railway dump source version
- `migrate`: one-shot database initialization / lightweight migration
- `bot`: Discord worker
- `api`: FastAPI admin API, internal only
- `frontend`: Next.js admin UI, public

## Coolify Resource

Create a new resource in Coolify:

```text
Type: Docker Compose application
Repository: this repository
Base directory: /
Docker Compose file: docker-compose.coolify.yml
```

Publish only the `frontend` service on container port `3000`. The API stays on
the internal Compose network and the frontend reaches it through
`API_URL=http://api:8000`.

## Variables

Set these in Coolify. Only `DISCORD_TOKEN` has to be filled manually before
the first deploy; the other values are usable defaults and can be changed later:

```env
DISCORD_TOKEN=...
ADMIN_USER=admin
ADMIN_PASSWORD=itsuka-admin-password
SESSION_SECRET_KEY=itsuka-session-secret-change-me-before-production
SERVICE_PASSWORD_POSTGRES=itsuka-postgres-password
SERVICE_URL_FRONTEND_3000=https://your-itsuka-bot-domain.example.com
CORS_ORIGINS=https://your-itsuka-bot-domain.example.com
SECURE_COOKIE=true
LOG_LEVEL=INFO
```

`SERVICE_PASSWORD_POSTGRES` may also be generated by Coolify. `POSTGRES_DB` and
`POSTGRES_USER` default to `itsuka_bot` and `itsuka`.

Keep the actual production hostname only in Coolify Variables. Set both
`SERVICE_URL_FRONTEND_3000` and `CORS_ORIGINS` to that URL.

PostgreSQL 18 Docker images store data under a major-version-specific directory
below `/var/lib/postgresql`, so the Compose file mounts `postgres-data-18` at
`/var/lib/postgresql`. Do not change it back to `/var/lib/postgresql/data`.

## DNS

For the current home server / KAGOYA relay layout, point the app domain at the
same public endpoints as Coolify:

```text
your-itsuka-bot-domain.example.com A    203.0.113.10
your-itsuka-bot-domain.example.com AAAA 2001:db8::10
```

Then assign the same URL to the `frontend` service in Coolify.

## Railway Database Migration

Dump Railway PostgreSQL with a normal PostgreSQL URL, not the SQLAlchemy
`postgresql+asyncpg://` form:

```sh
pg_dump "$RAILWAY_DATABASE_PUBLIC_URL" \
  --format=custom \
  --no-owner \
  --no-acl \
  --file railway-itsuka.dump
```

Before the final dump, stop the Railway bot so the same Discord token is not
running in two places.

Restore into the Coolify PostgreSQL service from a shell that can reach the
Coolify database:

```sh
pg_restore \
  --dbname "$COOLIFY_DATABASE_URL" \
  --clean \
  --if-exists \
  --no-owner \
  --no-acl \
  railway-itsuka.dump
```

Use a `postgresql://...` URL for `pg_restore`.

## Cutover Checklist

1. Deploy the Coolify stack with the bot stopped or without `DISCORD_TOKEN`.
2. Confirm `frontend`, `api`, and `db` become healthy.
3. Stop the Railway bot.
4. Take the final Railway dump.
5. Restore the dump into Coolify PostgreSQL.
6. Start the Coolify bot.
7. Log in to `/login` and confirm the existing settings are visible.
